摘要

随着教育数字化转型的深入推进，高校教学场景对**个性化**、智能化教学资源的需求日益增长。传统教学模式存在资源生成效率低、个性化程度不足、教学反馈滞后等痛点，难以满足现代高等教育对因材施教的核心诉求。本项目\"知域\"旨在构建一个基于大模型的个性化资源生成与学习多智能体系统，通过融合**大语言模型**、**多智能体**协同技术、**知识图谱**与**检索增强**生成（RAG）技术，为高校教学提供智能化辅助平台。

系统核心功能包括：对话式学习画像动态构建（支持专业、课程、知识基础、认知风格等10个维度）、多智能体协同资源生成（5类个性化教学资源）、个性化学习路径规划、智能辅导与学习效果评估。系统采用前后端分离架构，前端基于Vue 3 + Element Plus + ECharts构建用户交互界面，后端基于Spring Boot 3 + MyBatis-Plus处理业务逻辑，数据层使用MySQL 8.0 + Redis + Neo4j，AI层集成大语言模型API与RAG技术实现智能问答与资源生成。

系统创新点包括：多智能体协同资源生成架构实现一键生成多类型教学资源；对话式画像构建支持自然语言交互，降低使用门槛；RAG技术结合知识库实现精准知识检索；知识图谱支撑个性化学习路径规划。系统为高校教师提供智能化教学资源生成工具，为学生提供个性化学习支持，推动AI与教育的深度融合。

关键词：大语言模型；多智能体；个性化学习；知识图谱；检索增强生成；教育信息化

Abstract

With the deepening of educational digital transformation, the demand for personalized and intelligent teaching resources in university teaching scenarios is growing rapidly. Traditional teaching models suffer from low resource generation efficiency, insufficient personalization, and delayed feedback, making it difficult to meet the core demands of modern higher education for individualized instruction. This project, \"Zhiyu\" (Knowledge Domain), aims to build a large model-based personalized resource generation and learning multi-agent system, providing an intelligent teaching assistance platform by integrating large language models, multi-agent collaboration technology, knowledge graphs, and Retrieval-Augmented Generation (RAG) technology.

The core functions of the system include: dynamic construction of conversational learning profiles (supporting 10 dimensions including major, courses, knowledge base, and cognitive style), multi-agent collaborative resource generation (5 types of personalized teaching resources), personalized learning path planning, intelligent tutoring, and learning effect assessment. The system adopts a front-end and back-end separation architecture, with the front-end based on Vue 3 + Element Plus + ECharts for user interaction, the back-end based on Spring Boot 3 + MyBatis-Plus for business logic, the data layer using MySQL 8.0 + Redis + Neo4j, and the AI layer integrating large language model APIs and RAG technology for intelligent Q&A and resource generation.

Keywords: Large Language Model; Multi-Agent; Personalized Learning; Knowledge Graph; Retrieval-Augmented Generation; Educational Informatization

一、前言

（一）研究背景

根据教育部发布的《教育信息化2.0行动计划》，我国教育信息化建设已进入深度融合创新阶段，推动信息技术与教育教学的深度融合成为当前教育改革的重要方向\[1\]。黄荣怀等学者指出，人工智能技术与学校教育融合成为一种未来趋势，这为个性化学习和个别化学习的实现提供技术保障，成为教育发展的重要推动力\[2\]。

然而，当前高校教学仍面临以下核心痛点：

（1）教学资源生成效率低：教师备课需要大量时间搜索、整理、编写教学材料，资源生成周期长、效率低。祝智庭等研究表明，传统教学资源开发模式难以适应快速变化的教学需求\[3\]。

（2）个性化程度不足：传统教学模式采用\"一刀切\"方式，难以满足学生差异化的学习需求。余胜泉指出，实现真正的因材施教需要借助智能技术对学习者进行精准画像与个性化推荐\[4\]。

（3）教学反馈滞后：学生学习效果的评估往往依赖期中、期末考试，反馈周期长，难以及时调整教学策略。

（4）学习路径缺乏规划：学生缺乏系统性的学习路径指导，学习目标不明确，学习效率低下。

与此同时，以大语言模型（Large Language Model, LLM）为代表的人工智能技术近年来取得了突破性进展。OpenAI发布的GPT系列模型、Google的Gemini、以及国内百度的文心一言、阿里通义千问、讯飞星火等大模型，在自然语言理解与生成方面展现出强大的能力\[5\]。这些技术为构建智能化教学辅助平台提供了新的技术路径。

在此背景下，利用大语言模型、多智能体协同、知识图谱以及RAG等技术，设计并实现一套面向高校教学的个性化资源生成与学习多智能体系统，兼具重要的理论意义与迫切的现实价值。

（二）国内外研究现状

1\. 国内研究现状

国内在智能教育领域的研究起步较早，研究重心经历了从数字化教学资源建设到智能化教学辅助的演变。黄荣怀等学者系统阐述了人工智能赋能教育的核心逻辑，提出\"教育的智能化不是技术堆砌，而是以人为本的转型升级\"，强调智能技术应服务于教学本质\[2\]。

祝智庭等从教育数字化转型的视角出发，分析了智能教育的发展趋势与关键特征，指出个性化学习、自适应学习、智能评测等是智能教育的核心应用场景\[3\]。

余胜泉深入研究了人工智能教师的未来角色，提出AI教师将在个性化辅导、学习分析、资源推荐等方面发挥重要作用，但强调人机协同而非人机替代\[4\]。

在大模型教育应用方面，国内学者进行了积极探索。陈丽等研究了教育信息化2.0时代的智慧教育建设路径，提出构建\"云-网-端\"一体化的智慧教育环境\[6\]。

在多智能体系统方面，国内研究主要集中于多智能体协同机制、任务分配算法等领域。知识图谱在教育中的应用研究也取得了一定进展，主要用于知识点关系建模与学习路径推荐。

2\. 国外研究现状

国外在智能教育领域的探索起步更早，研究层次也相对深入。OpenAI的GPT系列模型在教育领域展现出强大潜力，Khan Academy已推出基于GPT-4的AI助教Khanmigo，实现了个性化辅导与答疑\[7\]。

在检索增强生成（RAG）技术方面，Lewis等提出了RAG的基本框架，通过将外部知识库与生成模型结合，显著提升了问答系统的准确性与可解释性\[8\]。

在知识图谱方面，Wang等系统综述了基于大语言模型的自主智能体研究，指出知识图谱与智能体的结合是未来发展的重要方向\[9\]。

然而，已有研究普遍存在系统集成度不足的问题，对话、资源生成、路径规划等功能往往分散在独立系统中，缺乏统一的教学辅助平台，且对大模型在教育场景中的系统性应用关注不够。本课题在综合借鉴上述研究的基础上，力求构建一套功能完整、技术先进、注重实用性的智能教学综合系统。

二、系统分析

（一）需求分析

1\. 用户需求分析

本系统面向高校教学场景，主要服务于以下三类用户：

教师用户：需要智能化教学资源生成工具，减轻备课负担；需要了解学生学习情况，进行针对性教学；需要管理课程、作业、考试等教学活动。

学生用户：需要个性化学习路径指导；需要智能辅导解答学习困惑；需要了解自身学习效果，明确提升方向。

管理员用户：需要进行用户管理、课程管理、系统配置等维护工作。

2\. 功能需求分析

（1）用户服务模块

支持用户注册、登录、身份认证、信息管理等功能；提供基于JWT的Token认证机制；支持教师、学生、管理员多角色权限管理。

（2）对话式学习画像构建模块

支持学生通过自然语言输入学习情况；自动抽取并构建包含专业、课程、知识基础、认知风格等10个维度的动态画像；画像数据为后续个性化推荐提供数据支撑。

（3）多智能体协同资源生成模块

SyllabusAgent实现课程讲解文档智能生成；MindMapAgent实现知识点思维导图自动生成；QuestionBankAgent实现分层练习题与测评题生成；MediaAgent实现多模态视频/动画脚本生成；CodingAgent实现代码实操案例与实践项目材料生成。

（4）个性化学习路径规划模块

根据学生阶段、目标与画像生成动态学习路径；推送讲义精读包、知识脉络导图、分层练习题等资源；支持学习进度跟踪与路径动态调整。

（5）智能辅导模块

支持学习问题输入，输出Markdown结构化讲解；提供图解建议、短视频讲解建议、参考资料建议；结合RAG技术实现精准知识检索。

（6）学习效果评估模块

根据学习任务完成度、刷题情况、学习时长等数据综合评估；输出准确率、活跃度、完成度、学习稳定性等指标；生成诊断结论与优化建议。

3\. 非功能需求分析

性能需求：系统响应时间不超过3秒，支持并发用户100人以上。

可用性需求：系统可用性达到99.5%以上，支持故障自动恢复。

可扩展性需求：采用模块化架构，支持功能模块的独立扩展。

安全性需求：数据传输加密存储，防止SQL注入、XSS等攻击。

兼容性需求：支持主流浏览器（Chrome、Firefox、Edge等）访问。

（二）可行性分析

1\. 技术可行性

本系统采用成熟的技术栈：前端使用Vue 3 + Element Plus，后端使用Spring Boot 3 + MyBatis-Plus，数据库使用MySQL + Redis + Neo4j，AI层使用大语言模型API + RAG技术。这些技术均有成熟的社区支持与丰富的文档资源，技术实现可行。

2\. 经济可行性

系统开发主要依赖开源技术框架，无需购买商业软件许可。大语言模型API调用成本可控，通过RAG技术可减少不必要的API调用。系统部署可采用Docker容器化方案，降低运维成本。

3\. 法律可行性

系统遵守《中华人民共和国网络安全法》《中华人民共和国数据安全法》等相关法律法规。用户数据采用加密存储，隐私保护措施完善。系统内容生成基于用户输入与知识库，不涉及版权侵权问题。

三、系统关键技术

（一）Spring Boot 3后端框架

Spring Boot 3是基于Spring Framework 6构建的快速开发框架，采用Java 17作为最低版本要求。本系统使用Spring Boot 3.2版本，主要特性包括：

（1）自动配置：根据项目依赖自动配置Spring应用，减少繁琐的XML配置。

（2）内嵌服务器：内置Tomcat服务器，无需额外部署WAR文件。

（3）微服务支持：与Spring Cloud生态良好集成，支持微服务架构扩展。

（4）安全框架：集成Spring Security，支持JWT认证与权限控制。

（二）Vue 3前端开发框架

Vue 3是渐进式JavaScript框架，采用Composition API提升代码复用性。本系统使用Vue 3.4版本，配合Vite构建工具，主要特性包括：

（1）Composition API：通过setup函数组织逻辑，提升代码可维护性。

（2）响应式系统：基于Proxy的响应式机制，性能优于Vue 2的Object.defineProperty。

（3）组件化开发：支持单文件组件（SFC），模板、脚本、样式集中管理。

（4）TypeScript支持：原生支持TypeScript，提升代码类型安全性。

（三）大语言模型API集成技术

本系统通过RESTful API集成主流大语言模型，实现自然语言理解与生成能力。技术要点包括：

（1）统一接口封装：封装不同厂商的API接口，提供统一的调用方式。

（2）流式输出：采用SSE（Server-Sent Events）技术实现流式响应，降低用户等待时间。

（3）Prompt工程：设计结构化Prompt模板，引导模型生成符合要求的输出。

（4）上下文管理：维护对话历史上下文，支持多轮对话交互。

(四) 检索增强生成技术（RAG）

RAG（Retrieval-Augmented Generation）是一种结合信息检索与文本生成的技术框架。本系统使用RAG技术实现智能辅导功能，完整流程包括文档处理、向量化、混合检索与上下文增强。主要技术要点：

（1）文档分块与预处理：将知识库文档按800字符粒度切分（含250字符重叠，重叠率31%），支持 PDF/Word/TXT多格式解析（Apache PDFBox/POI/Tika）。分块时优先在句号、问号、感叹号处切分，识别章节标题（\"第X章\"等），确保语义边界不被破坏。

（2）向量化方案选型与实测：经5轮对比测试，最终选用n-gram TF-IDF（256维）作为生产Embedding方案：

\| 方案 \| 结果 \| 原因 \|

\|\-\-\-\-\--\|\-\-\-\-\--\|\-\-\-\-\--\|

\|Mock SHA-256 (384d) \| 0% 命中率 \| 哈希向量无语义相似性 \|

\|DeepSeek /v1/embeddings \| 不可用 \| DeepSeek 不支持该端点 \|

\|HuggingFace all-MiniLM-L6-v2 \| 不可用 \| 模型下载被墙 \|

\|n-gram TF-IDF (256d) \| 100% (小规模) / 72% (10\^4 规模) \| ✅ 纯本地计算，零成本 \|

n-gram TF-IDF将文本中1-3字的高频片段作为特征维度，通过TF-IDF权重计算向量并L2归一化。对中文技术文本（术语标准化程度高），其命中率与真实 Embedding差距约13-20个百分点，但无需任何 API Key 或网络依赖。

（3）向量存储与检索：使用 Chroma VectorDB（Docker部署，cosine距离，HNSW 索引）存储文档向量。检索时取Top-5结果，支持按课程名过滤。10\^4文档规模下查询耗时\<100ms。

（4）混合检索与降级策略：采用双路径检索架构------优先走Chroma向量语义检索；若Chroma不可用或返回空，自动降级为MySQL关键词匹配（2-5字滑动窗口分词+全文匹配）。确保在任何部署环境下都有可用的事实基础注入能力。

（5）上下文增强：将检索到的文档片段按【参考资料 X】标题-章节格式拼接注入System Prompt，并附引用标注要求。LLM基于此上下文生成回答，前端通过SSEcitations事件展示引用来源（支持点击跳转PDF页码）。

（6）10\^4规模批量验证：编写独立测试脚本（rag_bulk_test.cjs），生成 10,000篇文档（20 CS主题）、100组查询进行批量检索。Top-1命中率72%，Top-3命中率77%，MRR0.745，总耗时5.2秒。详细报告见\[rag-optimization.md\]

（五）多智能体协同调度技术

本系统采用多智能体架构实现教学资源生成，技术要点包括：

（1）统一Agent接口：定义统一的Agent接口规范，包含generate、validate等方法。

（2）智能体注册机制：支持动态注册与卸载智能体，便于扩展。

（3）任务调度器：根据资源类型选择对应智能体，协调多智能体并行工作。

（4）结果聚合：整合多个智能体的生成结果，输出完整资源包。

（六）知识图谱构建技术

本系统使用Neo4j图数据库构建课程知识图谱，技术要点包括：

（1）节点建模：定义知识点、课程、章节等节点类型及其属性。

（2）关系建模：定义知识点之间的依赖关系、归属关系等。

（3）图谱可视化：使用ECharts Graph组件实现知识图谱的可视化展示。

（4）路径查询：基于图算法查询知识点之间的最短路径，支撑学习路径规划。

(七) AI 生成内容防幻觉技术

大语言模型存在\"幻觉\"问题------即生成看似合理但事实错误或完全虚构的内容。在教育场景中，幻觉可能导致学生学到错误知识，风险极高。本系统构建了7层防幻觉防护体系，以下为各层具体实现：

（1）输入安全过滤：在TutorServiceImplWithRAG.validateRequest()中对用户提问做敏感词检测（作弊/违法/恐怖/色情/暴力），命中即拒绝请求并抛出IllegalArgumentException，从源头阻断有害输入。

（2）RAG事实基础注入：支持PDF/Word/TXT多格式文档解析，按800字符粒度切片（250 字符重叠），通过n-gramTF-IDF 256维向量化后存入Chroma向量数据库（cosine距离，HNSW索引）。检索Top-5结果后动态注入 System Prompt，并附\`【参考资料 X】\`引用标注要求。当Chroma不可用时自动降级为MySQL关键词兜底检索，确保在任何环境下都有事实基础。详见 \[rag-optimization.md\](rag-optimization.md)。

（3）Prompt工程约束：所有System Prompt统一追加不确定性声明（\"如果你不确定答案，请明确说\'我不确定\'或\'我目前没有足够的信息回答这个问题\'，不要猜测或编造内容\"）。限定角色为高校教学场景，要求结构化输出（Markdown/JSON），Temperature从默认0.7降至0.4（降低随机性，减少幻觉概率）。Agent 模块的3个方法（知识讲解/学情诊断/路径规划）已全部接入RAG，消除了裸调LLM的幻觉风险敞口。

（4）LLM可控调用：通过LLMClient（OkHttp）以OpenAI兼容协议调用 DeepSeek API，显式配置Temperature=0.4、Max Tokens=4096。连接超时30s，读取超时180s，三层降级（null→静态模板→前端兜底）确保极端情况下系统仍可用。

（5）输出安全过滤：filterOutput()方法对LLM返回内容做与输入层相同的敏感词扫描（复用blockedWords配置），命中则替换为安全提示（Tutor返回 Markdown 安全提示，Agent/Companion 返回结构化兜底回复）。覆盖buildAnswer()、stream()、knowledgeExplain()、diagnosis()、pathPlanning()、courseRecommend()、chatStreamWithCompanion()共7个方法。

（6）RAG 接地验证：在buildAnswer()中引入检索增强校验------若RAG检索到资料但LLM输出未包含\"参考资料\"标注，自动向safetyTips追加\"⚠️AI回答未明确标注引用来源，建议核实关键信息\"，强化回答的可追溯性。Agent模块的RAG检索失败时静默降级（仅log.warn），不影响主流程。

（7）LLM 不可用降级：三层降级策略------L1:LLMClient返回null（API未配置/超时/异常）；L2:各Service使用专用fallback方法（Tutor用buildFallbackMarkdown()生成结构化模板，Agent用4个专用fallback，Companion用fallbackCompanionReply()）；L3:前端显示\"网络异常/服务繁忙\"兜底提示（AIFloatingBall.vue、AIDialogBar.vue）。

2\. RAG知识检索功能

![](media/image13.png){width="5.941666666666666in" height="2.9923611111111112in"}图5.8 RAG知识检索功能界面图

系统结合RAG技术实现精准知识检索。当学生提问时，系统首先在向量数据库中检索相关知识片段，然后将检索结果作为上下文输入大模型生成回答。这种方式有效解决了大模型\"幻觉\"问题，提升了回答的准确性与可靠性。

RAG实现流程：

（1）文档加载：从知识库加载课程文档。

（2）文档分块：将文档切分为适当大小的文本块。

（3）向量化：使用Embedding模型将文本块转换为向量。

（4）向量存储：将向量存入向量数据库。

（5）相似度检索：根据查询检索最相关的文本块。

（6）上下文增强：将检索结果作为上下文生成回答。

七、系统总结

本项目成功设计并实现了\"知域\"------基于大模型的个性化资源生成与学习多智能体系统。系统主要完成了以下工作：

（1）构建了对话式学习画像动态构建机制，支持10个维度的学生画像自动抽取与更新，为个性化学习提供数据基础。

（2）实现了5类专业智能体协同资源生成架构，支持一键生成课程讲解文档、思维导图、分层练习题、视频脚本、代码案例等个性化教学资源。

（3）设计了个性化学习路径规划算法，基于知识图谱与学生画像生成动态学习路径，实现因材施教。

（4）实现了智能辅导功能，结合RAG技术提供精准的知识检索与结构化回答。

（5）构建了教师端/学生端双端系统，支持完整的教学管理流程。

系统创新点包括：多智能体协同架构实现高效资源生成；对话式画像构建降低使用门槛；RAG技术提升辅导准确性；知识图谱支撑路径规划。系统为高校教学提供了智能化辅助平台，推动了AI与教育的深度融合。本系统已申请软著。
